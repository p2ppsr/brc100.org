01 / THE STANDARD

More than a wallet balance.

BRC-100 defines how an application asks a wallet to act. The wallet handles the keys, permissions, and implementation.

01

Payments & transactions

Create actions, accept incoming transactions, and organize outputs into baskets. Build the experience your application needs.

createActionlistOutputs
02

Keys & cryptography

Request public keys, sign data, and encrypt messages within a protocol context. Private key handling stays with the wallet.

getPublicKeyencrypt
03

Identity & certificates

Work with identity certificates and selectively reveal fields to a verifier. Ask for the information your application actually needs.

acquireCertificateproveCertificate
↔

The interface is the agreement. Apps target a common API; wallets can have different user experiences, storage, and service choices. Check support and permission behavior in the implementations you target.

A FEW GOOD QUESTIONS

Before you build.

Is BRC-100 a wallet, a token, or a company?+

It’s an open wallet-to-application interface specification for BSV. Wallets implement it; applications use it. BRC-100 itself is not a wallet product or a token.

Do I need a wallet to use this explorer?+

No. This explorer displays code and request shapes locally. To run that code in an application, use the SDK with a compatible wallet. The wallet may request user authorization.

Does one interface make every wallet identical?+

The API gives applications a common contract. Wallet UX, supported transports, permission policies, storage, backup, and recovery can differ. Test against your target implementations rather than assuming identical behavior.

Where can I ask questions or contribute?+

Start with the BRCs repository (opens in a new tab) for specification discussions. For an implementation issue, use that project’s repository and include a minimal reproducible example.
